## Replacement telemetry contract

MapServer 62 fields are OBJECTID, Shape, record_date (date), plow_status/spreader_status/engine_status (strings), truck (integer), latitude/longitude (double). Actual flags are `True`/`False` strings. Native source CRS is EPSG:4326; the map extent's EPSG:26917 is not the source coordinate system. OBJECTID is the OID field, inferred from its declared type because `objectIdField` is absent in this MapServer metadata.

The layer declares `Eastern Standard Time`, `respectsDaylightSaving=true`, and does not declare unknown-timezone dates. Direct feature date values are UTC epoch milliseconds. WHERE date literals follow the declared source timezone. The layer supports count, order, pagination, ID queries and statistics, with maximum feature transfer 2,000. Extraction uses 500-ID batches, rejects truncation and reconciles ID sets/count/schema afterward. No edit-history or transaction-isolated snapshot was established. There is no claim that OBJECTID survives reloads.

The CSV keeps truck IDs as text and unzoned source-local timestamps. Portal normalization retains original attributes/OID/epoch and converts its **declared** clock to Toronto wall time, without rewriting CSV NTZ fields. All sampled payload coordinates/flags/timestamps agree exactly; integer → text identifier normalization is explicit. January 12's overlap is only one record, so that particular sample provides little additional confidence. Prior PR #18's 325 hourly comparisons and eight endpoints remain separate historical evidence; they were not repeated or represented as a fresh full-service equality test.

The five-hour MIN/MAX statistic versus direct feature timestamp pitfall from PR #18 remains relevant. Coverage above uses ordered direct feature dates, not MIN/MAX aggregate epochs or the scraper's metadata timezone. No new interpretation was invented from those statistics.

## Licences and reference geography

Windsor's [Open Government Licence v1.0](https://opendata.citywindsor.ca/Documents/OpenDataTermsofUse.pdf) permits reuse with attribution and excludes personal information, protected/third-party rights and official marks. The application and reference artifacts carry the required attribution. Detailed telemetry and request addresses are not published. Current portal template placeholders in copyright descriptions do not establish a department, sync schedule or historical validity.

The legacy road fields include FULL_NAME, COMPKEY, RD_CLASS, TRUCK_ROUT, BUS_ROUTE, speed/lanes and address ranges. Only road key/name/class/status and geometry enter the public context projection; address ranges and other unnecessary fields are omitted. Provider RD_CLASS values include `L/R`, `C1_ART`, `C1_COL`, `C2_ART`, `C2_COL`, `EXP`, `LCI`, `PCI`, `S_PKWY` and blank. No authoritative maintenance-priority assignment was obtained. A road classification is geographic/network context, not an assigned snow route. The current-versus-legacy feature difference of eight is not proof of eight newly constructed roads: representations/segmentation can differ.

Leaflet **1.9.4** JS/CSS and its BSD-2-Clause licence are vendored from the published package. [Leaflet reference](https://leafletjs.com/reference.html) provides EPSG:3857 display and GeoJSON overlays; manual point/line calls reorder lon/lat to Leaflet lat/lng. [MapLibre](https://maplibre.org/maplibre-gl-js/docs/) is a capable WebGL alternative, but its style/rendering machinery adds little for this scale. No OSM tiles are requested, no tile scraping occurs and no private coordinates go to an external basemap. The bundled street network is the map fallback itself.

Edmonton's [Open Government Licence v1.0, July 2022](https://data.edmonton.ca/stories/s/City-of-Edmonton-Open-Data-Terms-of-Use/msh8-if28/) requires source attribution. The three-record fixture is a tool-retrieved API JSON excerpt, not a raw-byte snapshot archive. `municipal_status.py` preserves provider attributes and treats `NA` as unavailable. It deliberately has no telemetry observation metric. A future status history would need event identity, effective/update times, revision semantics and an independently validated definition of completion before comparison with Windsor outcomes.

## Acquisition size and boundaries

Seven actual CSV downloads total **26,676,398 bytes**, including **3,209,150** new February bytes. The first small expansion was checked before the subsequent bounded weeks were analyzed; all three preserve the same explicit parsing policy and were processed separately. Snapshot extraction recorded **83 API GETs, 6,824,892 response bytes, zero retries**, including the first failed road-schema attempt. This ledger excludes discovery/catalogue reads, assets/dependency installation, seven CSVs and the legacy road ZIP; it is not a claim that 83 covers every network request during the assignment. Eight accepted bounded ArcGIS scopes contain 12,854 retrieved features (including road/boundary/request context and overlap), not 12,854 new telemetry events.

Raw responses, source CSVs, exact snapshots, request addresses, original points and the local detail file remain outside public Git. The private replay package preserves reconstruction inputs; public Git contains contracts, non-identifying aggregates and official road/boundary geometry. **Zero weather API calls and zero Databricks calls.**
